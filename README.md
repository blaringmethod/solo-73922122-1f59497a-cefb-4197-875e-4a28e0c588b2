# 公共采购公告采集系统

面向招标数据员的公告采集交付件：FastAPI 采集器 + 带限流/延迟/429 故障/跳转开关的本地模拟采购站，
Docker Compose 一键启动，浏览器即可启动采集、查看实时进度、停止任务并下载 JSON。

## 目录结构

```
.
├── docker-compose.yml          # 两服务编排：procurement-site + collector
├── collector/                  # 采集器（FastAPI + httpx + BeautifulSoup）
│   ├── Dockerfile
│   ├── requirements.txt
│   └── app/
│       ├── main.py             # API、JSON 下载、采购站同源代理、静态页挂载
│       ├── crawler.py          # 采集引擎：并发闸门、429 响应头即冷却、逐跳跳转、停止回收
│       ├── parser.py           # BeautifulSoup 列表/详情解析（失败抛 ParseError）
│       └── static/index.html   # 浏览器控制台（单文件，原生 JS）
├── site/                       # 本地模拟公共采购站
│   ├── Dockerfile
│   ├── requirements.txt
│   └── app/
│       ├── main.py             # 栏目/详情页、限流、慢传/断流429、同站跳转、请求时间记录
│       └── data.py             # 确定性内存数据集（含跨栏目重复编号与 1 个坏详情页）
└── tests/                      # 契约测试与解析器单测（标准库 + venv 依赖）
```

## 启动

```bash
docker compose up --build
```

| 入口 | 地址 | 说明 |
| --- | --- | --- |
| 采集控制台 | http://localhost:8000/ | 启动/停止/进度/事件/请求时间记录/下载 JSON |
| 采购站（同源代理入口） | http://localhost:8000/site/ | 浏览器入口，经采集器反代到站点 |
| 采购站开关管理 | http://localhost:8000/site/admin | 限流、延迟、慢传/断流 429、同站跳转开关 + 站点侧请求时间记录 |
| 采购站直连 | http://localhost:8080/ | 仅排障时使用 |

## 采集规则与实现对照

| 需求 | 实现 |
| --- | --- |
| 固定站点两个栏目，遍历分页列表及详情 | `Crawler` 配置 `/tenders`、`/awards`；首页解析 `data-total-pages` 后入队其余列表页，再逐条入队详情页 |
| 按公告编号去重 | 集合 `_seen_codes` 跨栏目去重；同编号只采一次详情，跳过计数在分栏目进度中可见 |
| 提取标题、采购单位、截止日期 | `parser.parse_detail_page`，缺任一字段即 `ParseError` |
| 可下载 JSON | `GET /api/records/download`，附件文件名带轮次 ID，含未完成页清单与请求时间记录 |
| 单进程同时只采一轮 | 单 uvicorn worker + `round_lock`；重复启动返回 `409` |
| 最多两个请求在途 | 全站共享 `asyncio.Semaphore(2)`，两个栏目共用 |
| **429 响应头到达即冷却** | `_send_once` 用 `client.send(stream=True)`：响应头到达即读整数 `Retry-After` 并延长全站冷却钟，随即 `response.aclose()` **关闭错误响应，不读正文、不等请求超时**；慢传/断流的 429 正文不再延后或遗漏冷却 |
| 后续 429 只能延长等待 | `_extend_cooldown` 取 `max(现有, now+Retry-After)` |
| 重试与同站跳转每一跳都遵守冷却 | 重试与手动逐跳跟随的跳转（`follow_redirects=False`）都先过 `_pass_gate`；仅跟随相对/同站 Location，跨站跳转拒绝；已发出的正常响应允许读完收尾 |
| 跳转不重置页重试计数 | 跳转链在单次尝试内部完成，不消耗、也不重置 `attempts`；单链最多 5 跳防循环 |
| 每页最多尝试三次 | 列表/详情统一 `_get_parsed_page`，传输错误、429、跳转失败、4xx/5xx、解析失败均消耗尝试次数 |
| 耗尽/解析失败须列出未完成页，不能报整轮成功 | 失败页进入 `unfinished`；轮次结束状态为 `partial` 而非 `completed` |
| 停止阻止排队/冷却请求，关闭在途请求并回收连接后才显示已停止 | `stop_round` 先置停止位，再 `aclose()` 关闭在途请求与连接池，`await` 轮次协程收尾后状态才变 `stopped`，随后重建客户端允许新轮 |
| 旧响应不能写入新轮 | 每轮生成 `round_id`，冷却唤醒与回写前校验；新轮重建客户端、状态与记录容器 |
| 请求时间记录 | 采集器侧每个请求（含 429 与每一跳跳转）记录时刻/URL/状态/耗时/备注，见控制台“请求时间记录”与下载 JSON 的 `request_log`；站点侧 `/site/admin` 表格与 `/site/admin/log` JSON 记录到达时刻，可对照验证冷却期无新请求 |

轮次状态机：`idle → running → completed | partial | stopped`（停止过程中短暂为 `stopping`）。

## 模拟采购站说明

- 数据集：36 条招标公告（6 个列表页）+ 24 条中标公告（4 个列表页），
  中标公告复用前 24 个招标编号，用于验证跨栏目去重；
- `ZB-2026-010` 详情页故意缺少“采购单位/截止日期”，用于验证三次解析失败后
  进入未完成页面列表、整轮标记为 `partial`；
- 限流为滑动窗口，默认 10 秒窗口 12 个请求，超限返回 `429` 与整数 `Retry-After: 5`；
- `/admin` 运行时可切换的本地开关（保存即重置限流计数）：
  - 限流开关、窗口容量、窗口秒数；
  - 每请求人工延迟毫秒；
  - **429 正文慢传**：响应头（含 Retry-After）立即返回，正文按设定毫秒缓慢滴传；
  - **429 断流**：响应头立即返回，正文永不传完（连接挂起）；
  - **同站跳转次数**：每个内容页先相对 `302` 跳转 N 次再出正文，每一跳都是真实请求、
    同样消耗限流窗口，可制造“跳转与冷却交错”的场景；
- `/admin` 页面底部与 `/admin/log`（JSON）展示站点侧请求时间记录（时刻/路径/状态）。

## 推荐演示流程

1. `docker compose up --build`，打开 http://localhost:8000/ ；
2. 直接点“启动一轮采集”：观察到 `partial`——35 条记录、1 个坏详情页在未完成列表中；
3. 在 `/site/admin` 把窗口容量调到 3：再启动一轮，观察控制台“全站冷却剩余”倒计时，
   冷却期间两个栏目均无新请求完成；
4. 开启“429 正文慢传 2000ms”或“429 断流”再跑一轮：控制台“请求时间记录”中 429 行的
   耗时只有几十毫秒（响应头到达即关闭，不等正文），冷却照常开始；
5. 把“同站跳转次数”设为 1 并收紧限流：跳转每一跳都记录在请求时间记录里，
   对照 `/site/admin` 的站点侧请求时间记录，冷却窗口内（除已在途收尾外）无新到达请求；
6. 冷却进行中点“停止”：状态在 1 秒内变为 `stopped`，排队/冷却中的页面进入未完成列表；
7. 立即再启动一轮：状态与记录完全重置，证明旧轮响应不会写入新轮；
8. 点“下载 JSON”获取结构化结果（含未完成页清单与请求时间记录）。

## 本地测试（无需 Docker）

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r collector/requirements.txt
.venv/bin/python -I tests/test_parser.py
.venv/bin/python -I tests/test_crawler_contract.py
```

契约测试用内存假上游（支持分块流式响应）验证八件事：

1. 在途请求峰值恰为 2，整轮成功；
2. 429 后整站等待不少于 Retry-After 且重试可恢复；
3. 冷却中停止后零请求泄漏；
4. 停止后新轮干净无旧数据；
5. **慢传 429**：下一次请求在 Retry-After 后即发出（不等 1.5 秒正文滴传），429 日志耗时仅计响应头；
6. **断流 429**：正文永不传完时整轮仍在数秒内完成（不耗 15 秒请求超时）；
7. **跳转与冷却交错**：相对 302 逐跳跟随，服务器侧到达时间证明每一跳都守在冷却之后；
8. **跳转循环**：单链 5 跳上限，整页恰 3 次尝试后列入未完成——跳转不重置重试计数。
